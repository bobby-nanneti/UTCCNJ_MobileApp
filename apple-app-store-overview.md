# Apple App Store Overview for UTCCNJ Mobile App

## Goal
Move the Flet-based church app into the Apple App Store as a real iOS app.

## Core reality
This app is already built with Flet (Python + Flutter). That means it can be packaged for iOS, but Apple still treats it like a normal iOS app for:
- signing
- App Store Connect setup
- privacy review
- build certification
- app review approval

## Required pieces

### 1. Apple Developer Program
You must join the Apple Developer Program.
- Cost: about $99/year
- Needed for: App Store upload, certificates, provisioning, App Store Connect access

### 2. Mac or macOS build environment
This is the biggest practical requirement.
- iOS builds usually need a Mac with Xcode installed
- or a CI/macOS runner that can build and sign the app

Important note from this project:
- Android builds can be done from Windows
- iOS builds normally require a Mac/Xcode or CI runner

### 3. App Store Connect setup
Inside App Store Connect, you create and configure:
- app record
- bundle identifier
- app name
- category
- pricing
- privacy policy URL
- support URL
- screenshots
- metadata
- release version information

### 4. Production iOS build
The app must be built as a release artifact, not just run in dev mode.

Dev mode examples:
- `flet run --ios`
- `flet run -w`

These are only for local testing and LAN testing.

Production build path:
- signed app package generated by Flet/Flutter iOS build flow
- uploaded to App Store Connect

### 5. Privacy and legal requirements
Apple will review app compliance, including:
- privacy policy
- data usage explanation
- sign-in/login handling
- storage of member data in Supabase
- whether user data is collected and retained

Your app likely involves:
- phone/email lookup
- church member identity
- role-based access
- backend data access through Supabase

This should be documented clearly in the app and in the privacy policy.

## Typical submission flow
1. Join Apple Developer Program
2. Create App ID / bundle ID
3. Generate certificates and provisioning profiles
4. Build the app on a Mac/Xcode environment
5. Archive and upload to App Store Connect
6. Add metadata, screenshots, and app info
7. Test via TestFlight if desired
8. Submit for App Review
9. Release after approval

## What Apple will care about
Apple review commonly checks for:
- consistent app metadata
- valid app icon and screenshots
- proper privacy disclosures
- working login and core functions
- no debug/test-only behavior left in the release
- no broken or misleading app content

## Practical setup recommendation
The best order is:
1. Get Apple Developer Program enrollment
2. Set up Mac + Xcode
3. Make sure the app is stable in release mode
4. Build signed release artifact
5. Upload to App Store Connect
6. Test with TestFlight
7. Submit for review

## Cost summary
- Apple Developer Program: about $99/year
- Mac/Xcode environment: required for iOS build/signing

## Bottom line
To publish this church app to the Apple App Store, you need:
- Apple Developer account
- Mac/Xcode or CI runner
- signed iOS production build
- App Store Connect project
- privacy and legal metadata
- Apple review approval
